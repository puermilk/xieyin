## 4. 逐条译文对照

### ADN-451
- 原文：義父に10秒だけの約束で挿入を許したら…相性抜群過ぎて絶頂してしまった私。
- 参考：说好只让公公插入十秒，结果实在太合拍，我竟然高潮了。
- **LLM（2）**：答应公公只插10秒就让他进来，结果契合度实在太好，我直接高潮了。
- MyMemory（1）：当我允许我的岳父插入它时，承诺只有10秒钟......我高潮了，因为我太兼容了。
- 判定：LLM 全术语命中；MyMemory 義父→岳父、插入对象错、“太兼容”生硬。

### ADN-503
- 原文：私を舐め●す義父の接吻
- 参考：公公把我全身舔遍的吻
- **LLM（1）**：舔遍我的公公的接吻
- MyMemory（1）：岳父●舔我的吻
- 判定：LLM 术语全中、● 已还原，但“舔遍我的公公的接吻”语序不自然；MyMemory 保留 ● 且義父错译。

### ADN-556
- 原文：私は義理の息子とセックスしています。
- 参考：我和继子在做爱。
- **LLM（2）**：我正在和继子做爱。
- MyMemory（1）：我正在和我的女婿做爱。
- 判定：LLM 关系词正确且自然；MyMemory 義理の息子→女婿。

### DASS-659
- 原文：華奢スレンダーで清楚な妻が俺の親父に寝取られ種付けプレスされていた。
- 参考：娇小纤细、清纯的妻子被我亲爹睡了，还被按住播种内射。
- **LLM（1）**：纤细苗条又清纯的妻子，被我的父亲NTR，并被按住播种内射了。
- MyMemory（1）：一个华丽苗条而清晰的妻子被我父亲戴绿帽子和按压。
- 判定：LLM 漏了 must_term「亲爹」（译成“父亲”）且混入英文 NTR；MyMemory 多处误译、漏“内射”。

### IPZZ-542
- 原文：「おち〇ちん勃起させてごめんね。」 義理の息子が女湯でフル勃起！？戸惑った義母がこっそりヌイてあげるも自身も欲求不満なので性のおもちゃにシテあげた
- 参考：「对不起让小弟弟硬起来了。」继子在女澡堂全硬了！？不知所措的继母偷偷帮他撸，可自己也欲求不满，索性把他当成了性玩具
- **LLM（2）**：「对不起，让小鸡鸡勃起了。」继子在女澡堂完全勃起！？困惑的继母悄悄帮他撸出来，但自己也欲求不满，于是把他当成性玩具。
- MyMemory（0）：“对不起，把你的老二弄硬了。” “我女婿在女澡堂里完全勃起了！ ？我困惑的婆婆偷偷摸摸地摸索着我，我很沮丧，所以我把它给了一个性玩具。
- 判定：LLM 长句完整、关系词全对；MyMemory 关系词全错、后半句语义崩坏。

### ALDN-239（补充）
- 原文：お義母さん、にょっ女房よりずっといいよ…
- 参考：继母，你比我老婆好太多了……
- **LLM（2）**：继母，你比老婆好太多了…
- Google（1）：你婆婆比我老婆好多了...
- 判定：Google 把お義母さん译成婆婆；LLM 正确。

## 7. 最终推荐

### 主选：OpenCode Go `deepseek-v4.1-flash`
理由：12 条实测均分 1.75、0 分率 0%、术语命中 95%，是唯一能稳定处理 義父/義理の息子/義理の母 和 ● 打码字的源；本机直连可用，¥1.63/千条。

风险：
1. **延迟**：均 4.38s、P95 5.78s、最慢 6.59s，约是 MyMemory 的 3.2 倍；1000 条串行约 1.5 小时（含 1.6s 间隔）。
2. **依赖单点**：Cloudflare 会拦 Python 默认 UA（实测 `403 error code: 1010`），必须固定浏览器 UA；`x-opencode-session` 缺失即 400；订阅额度/QPS 规则未验证。
3. **术语仍非 100%**：DASS-659 的“亲爹”仍译成“父亲”并混入英文 NTR；打码字靠提示词还原，存在模型猜错的空间。

### 备选：Azure AI Translator F0
理由：官方 API、本机直连可达、2M 字符/月免费（约 7 万条/月），超出 $10/M ≈ ¥2.02/千条，适合做主选故障时的兜底。

风险：
1. **质量未实测**（无 key），不能保证达到 1.75；只能确认链路可达（404）。
2. **术语控制弱**：标准文本 API 无内嵌术语表，只有 Custom Translator，接入成本高。
3. **内容策略**：成人向标题可能触发服务条款/内容过滤，未验证。

## 8. 替换草案（不改现有签名）

目标文件仍是 `src/xieyin/app/xieyin/scripts/translate_zh.py`，对外签名保持不变：

```python
translate_text(text: str, retries: int = 2) -> str
build_plot_zh(d: dict) -> str
```

草案要点（只写方案，本次未改产品代码）：

1. **术语表位置**
   - 新增 `src/xieyin/app/xieyin/data/glossary_ja_zh.json`，随包分发，进程启动时加载一次。
   - 初始条目：`義父/お義父さん→公公`、`義理の息子→继子`、`義理の母/お義母さん/義母→继母`、`人妻→人妻`、`中出し→内射`、`種付けプレス→按住播种内射`、`犯す→侵犯`。
   - 每次请求把命中的术语以“源→目标”列表注入 system prompt；LLM 提示词固定，`temperature=0`，`max_tokens=400`。
   - 译文落库前做 `must_terms` 子串校验；命中失败记 warning（不直接判死，因为中文可能有同义词）。

2. **● / 〇 打码字**
   - LLM 路线：提示词明确“●/〇 是打码占位符，按上下文还原被遮的假名再翻译，输出不得保留 ●/〇”；输出若仍含 `●`/`〇` 判失败。
   - 非 LLM 备选路线：先用小型还原表做确定性替换，再送翻译：`舐め●す→舐め回す`、`犯●れ→犯され`、`おち〇ちん→おちんちん`；未收录的掩码直接判失败，不猜。
   - 任何情况下都不把 `●` 原样留在中文词中（基线 `舐め●す→岳父●舔` 就是反例）。

3. **失败判定（译文质量门）**
   以下任一条件即 `raise TranslationError`：
   - HTTP 非 200、超时、返回体不是预期 JSON；
   - 输出为空、与输入完全相同（未翻译）；
   - 剩余假名比例 > 5%（排除标点，统计 `[ぁ-んァ-ヶ]`）；
   - 含连续英文单词 `[A-Za-z]{3,}`（白名单：型号代码如 `ADN`，但简介正文不应有）；
   - 含 `●`/`〇`；
   - 长度比不在 0.25–2.5（中文/日文字符数）；
   - 已知术语在源文出现、但译文中对应中文缺失（按术语表逐条查）。

4. **失败如何显式返回**
   - 不返回日文、不写缓存、不静默降级。
   - `translate_text` 抛 `TranslationError(code, provider, http, detail)`；`build_plot_zh` 不吞异常，由调用方决定“该条标记未翻译并重试/告警”。
   - 重试只针对 429/5xx/超时，最多 `retries=2`，退避 0.5s/1.5s；401/403 不重试。
   - 单次请求超时 8s（LLM 12s），避免基线单条最坏 +33.4s 的问题。
   - 缓存 key 改为 `sha256(provider + glossary_version + text)`，TTL 30 天；只有通过质量门的译文才写缓存；新增清除入口。

5. **批量与吞吐（可选，未实测）**
   - LLM 可把 20 条标题打包成一次请求，要求返回 JSON 数组；失败整批重试一次，再降级逐条。可把 reasoning 开销摊薄，但本次未验证。
